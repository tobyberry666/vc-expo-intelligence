# GitHub Pages 真实数据接入

目标：新浏览器直接看到真实融资与展会，详情提供原文链接；不依赖妙搭登录，不编造缺失字段。

1. 采集 TechCrunch RSS 和 Type One Energy 官方 RSS → 用离线测试验证已完成融资、排除传闻、基金募集、非法链接。
2. 校验同源 JSON 快照并加载到共享 store → 验证日期、坏响应、历史缓存和详情 ID。
3. 展示可核验来源、未知展商数量 → 浏览器验证首页、筛选、收藏和直达详情。
4. GitHub Actions 每六小时采集、构建、部署 → 核实云端运行和线上新浏览器。

## 数据边界

融资只提取明确的英文融资标题，不将完整文章转载或使用模型填补事实。日期是报道发布日期；金额、轮次来自标题，未明确提及的机构与赛道标为未披露/其他。不是全市场统计，当前中国创投覆盖有限。

展会来自 `data/expos.json`，为人工核实的主办方日程。CES、MWC、HANNOVER MESSE 2027 的官方链接保存在每条记录中。展会日程不会自动推算下一年；过期场次自动移除，新增年度需重新核实。中国展商名单未核实，所以显示未披露。

Python 标准库实现采集，不增加运行依赖。每个源超时 25 秒、响应限制 2 MB、拒绝 XML 实体，链接限制 HTTPS 和已知源。单源失败保留旧记录并警告；所有源失败停止部署，线上保留上一版本。保留最多 180 天、100 条融资。

浏览器始终重新获取快照，更新时间取采集时间，超过 48 小时警告。刷新按钮重新读取服务器快照，不直接启动网络爬虫。自动更新可能因 GitHub 调度延迟而晚于六小时。源的成功/失败状态保存在快照 `sources` 中。

## 运行

```sh
python -m unittest discover -s tests -p test_collect_feed.py
python scripts/collect-feed.py
npm run build
```

Pages 设置使用 GitHub Actions，工作流 `.github/workflows/pages.yml`：main 推送、手动执行、每六小时触发。生成 `404.html` 保持详情深链接可用；仅部署任务拥有 Pages 写权限。不需要 API 密钥或付费服务。
