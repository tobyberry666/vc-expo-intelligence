# GitHub Pages 真实数据接入

目标：新浏览器直接看到真实融资与展会，详情提供原文链接；不依赖妙搭登录，不编造缺失字段。

1. 采集 TechCrunch RSS 和 Type One Energy 官方 RSS → 用离线测试验证已完成融资、排除传闻、基金募集、非法链接。
2. 校验同源 JSON 快照并加载到共享 store → 验证日期、坏响应、历史缓存和详情 ID。
3. 展示可核验来源、未知展商数量 → 浏览器验证首页、筛选、收藏和直达详情。
4. GitHub Actions 每小时采集、构建、部署 → 核实云端运行和线上新浏览器。

## 数据边界

融资只提取明确的英文融资标题，不将完整文章转载或使用模型填补事实。日期是报道发布日期；金额、轮次来自标题，未明确提及的机构与赛道标为未披露/其他。不是全市场统计，当前中国创投覆盖有限。

展会来自 `data/expos.json`，为人工核实的主办方日程。CES、MWC、HANNOVER MESSE 2027 的官方链接保存在每条记录中。当前年度日期每小时解析官方页面，解析失败保留上次核实日期并提示；不推算下一年，新增年度需重新核实。过期场次自动移除。中国展商名单未核实，所以显示未披露。

Python 标准库实现采集，不增加运行依赖。每个源超时 15 秒，瞬时网络错误最多尝试 3 次并退避、响应限制 2 MB、拒绝 XML 实体，链接限制 HTTPS 和已知源。单源失败保留旧记录并警告；所有源失败停止部署，线上保留上一版本。保留最多 180 天、100 条融资。

浏览器启动时重新获取快照，页面打开期间每 5 分钟自动检查一次，更新时间取采集时间，超过 3 小时未采集提示更新延迟。刷新按钮重新读取服务器快照，不直接启动网络爬虫。自动更新可能因 GitHub 调度延迟而晚于一小时。源的成功/失败状态保存在快照 `sources` 中。

## 运行

```sh
python -m unittest discover -s tests -p test_collect_feed.py
python scripts/collect-feed.py
npm run build
```

Pages 设置使用 GitHub Actions，工作流 `.github/workflows/pages.yml`：main 推送、手动执行、每小时触发。生成 `404.html` 保持详情深链接可用；仅部署任务拥有 Pages 写权限。不需要 API 密钥或付费服务。

## 持续更新的实际限制

快照 `sources` 为新闻和展会来源记录 `checkedAt`（本次检查）、`lastSuccessAt`（最后成功）及状态。某源失败不会把它的最后成功时间改成当前时间。全部新闻源失败终止发布并保留线上版本；超过三小时无新采集会在网页提示延迟。

GitHub [官方文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule) 说明定时任务可能延迟或遗漏，公开仓库无活动 60 天会停用定时工作流。因此这是一小时更新目标，不是绝对实时服务保障。仓库维护者需要关注 Actions 失败通知和定时任务启用状态；不可把采集频率等同全网覆盖率。融资仅覆盖现有公开 RSS 可识别标题，中国机构覆盖有限；新展会年度和展商名单仍须核验。
